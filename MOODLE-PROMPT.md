# KSE Hub — Moodle через токен студента (бриф від 30.10.2026)

Ти — Claude Code у репозиторії KSE Hub. Це бриф від власника. Прочитай його повністю, перш ніж щось робити.

## ⚠️ Головне правило: лише акаунт власника

**Усе з цього брифу працює тільки для адмінів (`users.is_admin`), тобто лише на акаунті власника. Студентам не відкриваємо.** IT KSE дозволив відкрити всім, але власник вирішив спершу все випробувати на собі — з міркувань безпеки. Обмеження `adminOnly` у `server/src/routes/moodle.ts` і `user.isAdmin` у мініаппі не знімаємо, поки власник прямо не скаже «відкриваємо всім». Кожна нова функція — теж за цим обмеженням.

Правила з `CLAUDE.md` без винятків: спершу план і питання → «ок» → код; превʼю `?mock=1&theme=light|dark` (для цього брифу ще `&admin=1&grades=1`); скриншоти 375 і 430 px в обох темах, 3 слабкі місця; сервер — лише додаванням, з тестами; тексти через `tr('…', '…')`; один екран чи компонент — один коміт; після кроку — `PLAN.md`.
3. Міграції застосовуй сам із терміналу: кореневий `.env` має `DATABASE_URL` продової бази Neon (запуск через `node` + `postgres` з теки `server/`, як `scripts/run-sql.mjs`). Вхід у Neon через браузер не потрібен (там цикл перевірки Cloudflare).

## 1. Що вже є (працює на акаунті власника)

- Профіль → Підключення → «Оцінки з Moodle» (`client/src/components/modules/grades/MoodleGradesSheet.tsx`), видно лише адмінам.
- Вхід: «Відкрити Moodle» → `admin/tool/mobile/launch.php?service=moodle_mobile_app&…&confirmed=1&oauthsso=2` → вхід через Google → посилання «Натисніть тут, якщо додаток не відкривається автоматично» = `moodlemobile://token=BASE64(siteid:::token:::privatetoken)` → студент копіює → `POST /api/moodle/grades/connect`.
  - `oauthsso=2` обовʼязковий: Moodle KSE дає токен лише одразу після входу через Google (інакше «Плагін не ввімкнено або не налаштовано»).
  - Паспорт (`siteid = md5(wwwroot + passport)`) сервер обчислює сам — `windowState` у `server/src/utils/crypto.ts`, вікно 30 хв + попереднє. Клієнт нічого не зберігає (Telegram перезавантажує мініапп, поки студент у браузері).
  - Перевірки: сайт = teaching.kse.org.ua, акаунт Moodle = пошта KSE студента в KSE Hub.
- Сервер: `server/src/services/moodleGradesService.ts` (список дозволених функцій `READ_ONLY`), `server/src/utils/moodleToken.ts`, таблиця `moodle_ws_tokens` (міграція 019, токен AES-256-GCM, ключ `TOKEN_ENC_KEY` у Vercel — окремо від бази), приватний токен не зберігаємо.
- Ендпоінти (admin-only): `GET /api/moodle/grades/start`, `POST /grades/connect`, `GET /grades`, `GET /grades/:courseId`, `DELETE /grades`.
- Тести: `server/src/__tests__/moodleGrades.test.ts`.
- **QR-вхід не робимо:** Moodle видає токен за QR лише своєму офіційному застосунку (`apprequired`); обійти = видавати себе за застосунок.

## 2. Безпека (умова IT: інформаційна безпека й захист персональних даних)

- Токен має всі права застосунку Moodle (зокрема здавати роботи й писати повідомлення). Тому:
  - лише функції **на читання**, кожна нова — явно в `READ_ONLY` + тест, що інші відхиляються;
  - **ніколи**: здача/надсилання завдань, завантаження файлів, повідомлення, пости на форумах, початок/проходження квізів, позначки виконання, зміна профілю;
  - **не читаємо особисті повідомлення** Moodle (`core_message_*`) — як ЛС у Slack;
  - токен лише зашифрований, видаляємо при відключенні й коли Moodle його не приймає;
  - сирі тексти листів/постів не зберігаємо довше, ніж треба для показу.
- Власник засвітив свій перший токен у чаті — його мали скинути (Moodle → Налаштування → Ключі безпеки). Якщо Moodle віддає старий токен, нагадай.

## 3. Що робимо (порядок погоджено, кожен крок: план → «ок» → код)

### 3.1 Одне підключення: дедлайни й квізи з Moodle
Для підключеного через токен — дедлайни з самого Moodle, а не з експорту календаря й розбору листів:
- `core_calendar_get_action_events_by_timesort` — найближчі події й дедлайни лише своїх груп;
- `mod_assign_get_assignments` + `mod_assign_get_submission_status` — строк, жорсткий дедлайн, продовження, «здано», «чернетка не надіслана», «оцінено»;
- `mod_quiz_get_quizzes_by_courses` + `mod_quiz_get_user_attempts` — відкриття/закриття, кількість спроб, свій бал (лише читання).
Показуємо в «Дедлайнах» і на «Сьогодні» в поточному стилі. Корисне попередження: «є чернетка, але не натиснуто "Надіслати"». Посилання на календар лишається запасним шляхом для всіх інших. Не ламаємо наявні `moodleService.ts`, «Moodle без шуму», «здано ✓» з листів.

### 3.2 Пуш «Нова оцінка»
- Будильник (`cronService.ts`) раз на ~30 хв читає сповіщення Moodle (`message_popup_get_popup_notifications`) або порівнює журнал — що дешевше й надійніше, вирішимо в плані.
- Одне повідомлення: «ECON100 · Problem set 3 — 17,5 / 20» + перший рядок відгуку, кнопка відкриває оцінки курсу. Шаблон у `server/src/bot/messages.ts`, двомовно, без емодзі, з тестом. Поза бюджетом 3 пушів (це дані самого студента) — уточни у власника.
- Розділ «Оцінки» в загальному дайджесті — нові оцінки за добу.

### 3.3 Сторінка курсу
`client/src/components/modules/course/CoursePage.tsx` + `server/src/services/courseService.ts`: підсумок курсу, оцінки за завдання з відгуками, оголошення викладача (`mod_forum_get_forums_by_courses` + `mod_forum_get_forum_discussions`, форум новин курсу), пізніше матеріали (`core_course_get_contents`: файли, слайди, що додали нещодавно).

### 3.4 Copilot про оцінки
Інструмент у `server/src/ai/tools.ts` + `aiService.ts`: «яка в мене оцінка з ECON100?», «що ще не оцінили?», «який відгук на мідтерм?». Лише для того, хто підключив Moodle; лише читання через `MoodleGradesService`.

## 4. Інше, що висить (не з цього брифу)

- Slack-дайджест для всіх: власник перейменовує акаунт-читача на «KSE Hub Digest» і додає `SLACK_DIGEST_FOR_ALL=1` у Vercel.
- Читабельність Slack-дайджесту: пункти одного каналу зливаються — розділити (формулювання пише задача Claude в claude.ai за `server/scripts/slack-digest-task.md`, розкладку — `slackDigestText` у `messages.ts`).
- Задача Slack живе в claude.ai (домен `kse-hub.vercel.app` дозволено); задача в Claude Code на Mac вимкнена.

## 5. Як перевіряти

- `cd server && npm test` і `npx tsc --noEmit` після кожного серверного кроку.
- Мініапп: `cd client && npm run dev` → `http://localhost:5173/?mock=1&theme=light&admin=1&grades=1` (моки в `client/src/dev/mock.ts`, додавай нові для кожного екрана).
- Живу перевірку робить власник на своєму телефоні; Moodle-токен у чат не просимо і не приймаємо.
